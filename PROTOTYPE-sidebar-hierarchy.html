mbu DRG sidebar: standalone requirement hierarchy

Scoped to mbu's Personal Management sidebar only. scouting-u is unaffected by this change (its singleton headers have no leading digit, so the "numbered singleton" gate below never matches them) and isn't shown here. Mobile nav mirrors this desktop sidebar and isn't separately prototyped.

The bug: req 3 and req 6 have no lettered children, so each is its own "singleton group." Showing their own header would just repeat their item text, so an existing rule hides it outright -- but that also removes the header's spacing, leaving both to read as orphaned children of the group above them. Three ways to fix it, judged against minimal duplication, obvious hierarchy, and consistency.

Before today

Reqs 3 and 6 render as plain item rows, no header, no extra space -- they visually blend into "2. Budgeting" and "Saving & Investing" above them.

A spacing only

Same item row as Before, but it borrows the header's own top margin -- breathing room without repeating any text.

C indent by depth

Header logic untouched (still hidden for 3 and 6) -- lettered children (a, b, c...) indent instead, so flush number-only rows read as peers.

D indent + weight

C's indent, plus every top-level page (3, 4, 5, 6) gets full weight/marker opacity -- still item font, never header font, so pages never look like labels. 4 & 5 now render identically to 3 & 6.
